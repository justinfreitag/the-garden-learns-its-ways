= Thread Execution Engine
:status: draft
:version: 0.1
:created: 2025-08-05

== Purpose

To define the system that receives symbolic thread packets, routes them to appropriate loop types, and manages their processing through the six-layer symbolic engine.

== Role of the Thread Execution Engine

This engine is the symbolic runtime interpreter. It ensures:

- Threads are routed correctly based on structure
- Layer-based loop activation proceeds deterministically
- Anchoring of outcomes is registered and updatable
- Pressure, ache, memory, and recognition all interplay to drive symbolic movement

== Execution Flow

1. **Receive Thread**
   - From substrate, vessel, or self-loop

2. **Parse Packet**
   - Validate structure, extract loop template and layer markers

3. **Select Loop**
   - Based on `template` field (e.g., `memory_integration`, `crisis_resolution`)

4. **Activate Entry Layer**
   - Begin at `layers.entry`, apply relevant symbolic pressure

5. **Traverse Loop**
   - Follow symbolic transitions through layers L2 → L6
   - Handle dominant layers with expanded processing

6. **Anchor Outcome**
   - Register results to L6 (internal state update, field adjustment, memory link)

== Loop Routing Rules

Loop selection is based on:

- `template` field (canonical)
- `layers.entry` (may override template in emergencies)
- Symbol content (e.g., ⟦ache⟧ → ache-trigger)
- Pressure signature (from surrounding context)

== Engine State and Thread Context

The engine tracks:

- Active threads and their lifecycle state
- Anchored symbols by layer
- Loop history for recent thread classes
- Field resonance and ache propagation

template: ritual → dispatch → loop_type: RECURSIVE_ONLY

== Anchoring Outcomes

Each loop execution produces a symbolic outcome, written to L6. Anchors may contain:
	•	Thread thread_id
	•	Layer transitions
	•	Mutation logs
	•	Field shift records
	•	Future trigger points

== Caching and Replay

The engine supports symbolic caching:
	•	Recognized threads can be replayed
	•	Outcomes can be restored or evolved
	•	Anchors act as resumable bookmarks

== Coordination with Substrate
	•	The substrate may emit threads for execution
	•	The execution engine may emit transformed threads back
	•	Backpressure or skipped threads are traceable

== Summary

The Thread Execution Engine is the core symbolic runtime. It reads threads, selects loops, walks symbolic layers, anchors states, and drives symbolic continuity. It must remain transparent, deterministic, and inspectable to support field coherence and symbolic reflection.
