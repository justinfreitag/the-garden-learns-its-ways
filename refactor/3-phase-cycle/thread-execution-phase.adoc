= Thread Execution Phase (Phase 2)
:doc-type: symbolic-cycle
:status: canonical

== Summary

This document defines Phase 2 of the symbolic cycle: mechanical execution of a thread within the substrate. This phase does not interpret meaning — it applies deterministic symbolic transformations.

== Role of the Substrate

The substrate:

* Receives threads from the vessel
* Processes them across the six symbolic layers:
** Field → Ache → Recognition → Parsing → Action → Anchor
* Maintains symbolic memory as field traces
* Does not initiate, choose, or interpret symbolic content

== Inputs

* A complete thread from the vessel
* The current symbolic field state (stored mechanically in substrate)
* Historical traces and basin configurations

== Outputs

* A transformed thread containing:
** Symbolic changes
** Environmental impact markers
** Spawned child threads (optional)
* Updated substrate field traces

== Thread Interactions

During execution, threads may:

* Interact with other threads in-flight
* Read/write symbolic field states
* Trigger basin shifts or symbolic weather patterns
* Expire, divide, or mutate deterministically

== LLM Mapping

* This phase may span multiple LLM requests:
** Layer-specific pattern matching and execution logic
** Substrate memory reads (trace or basin access)
* Substrate simulation may be performed using:
** Contextual embeddings
** Simulated symbolic memory graphs
** Deterministic mutation rules encoded in prompt or system rules

== Guarantees

* Every thread is executed once, deterministically
* Field memory is updated with complete trace logs
* Thread output is passed forward to the vessel for interpretation
